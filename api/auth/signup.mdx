---
title: "POST /auth/signup — create a new account"
description: "POST /auth/signup creates a Relay account. Supply email, displayName (2–40 chars), and password (8–128 chars). Returns user profile and JWT access token."
---

The signup endpoint creates a new user account and immediately authenticates it. On success the server returns the new user's public profile together with a short-lived JWT access token. A long-lived refresh token is stored in an `httpOnly` cookie so that subsequent token rotations require no extra work from your client.

## Endpoint

```
POST /auth/signup
```

**Authentication:** none required.

## Request body

<ParamField body="email" type="string" required>
  A valid email address. Must be unique across all Relay accounts — a duplicate address returns `409 Conflict`.
</ParamField>

<ParamField body="displayName" type="string" required>
  The name shown to other users in conversations. Must be between 2 and 40 characters.
</ParamField>

<ParamField body="password" type="string" required>
  The account password. Must be between 8 and 128 characters.
</ParamField>

## Response

HTTP `201 Created`.

<ResponseField name="user" type="object">
  The newly created user's public profile.

  <Expandable title="user fields">
    <ResponseField name="user.id" type="string">
      Unique identifier for the user (UUID).
    </ResponseField>

    <ResponseField name="user.email" type="string">
      The email address used to register.
    </ResponseField>

    <ResponseField name="user.displayName" type="string">
      The display name chosen at registration.
    </ResponseField>

    <ResponseField name="user.avatarUrl" type="string | null">
      URL of the user's avatar image. `null` until a photo is uploaded.
    </ResponseField>

    <ResponseField name="user.createdAt" type="string">
      ISO 8601 timestamp of when the account was created.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="accessToken" type="string">
  A short-lived JWT used to authenticate subsequent API requests. Pass this value in the `Authorization: Bearer <token>` header. Expires in 15 minutes by default.
</ResponseField>

## Side effects

The response also sets a `relay_refresh` cookie with the following attributes:

| Attribute  | Value              |
|------------|--------------------|
| `HttpOnly` | `true`             |
| `SameSite` | `Lax`              |
| `Secure`   | `true` (production)|
| `Path`     | `/auth`            |
| Expiry     | 30 days by default |

The browser (or HTTP client) sends this cookie automatically on subsequent requests to `/auth/refresh` and `/auth/logout`. Do not read or forward the cookie manually.

## Example

```bash
curl -i -X POST https://api.relay.example.com/auth/signup \
  -H "Content-Type: application/json" \
  -c cookies.jar \
  -d '{
    "email": "ada@example.com",
    "displayName": "Ada Lovelace",
    "password": "correct-horse-battery"
  }'
```

```json
{

}
```

## Error responses

| Status | Condition |
|--------|-----------|
| `400 Bad Request` | One or more fields failed validation (missing, wrong type, or out of the allowed length range). The response body contains a `message` array describing each violation. |
| `409 Conflict` | An account with the supplied email address already exists. |
