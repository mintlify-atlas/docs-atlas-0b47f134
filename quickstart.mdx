---
title: "Get started with Relay"
description: "Clone the repo, configure your environment, and have Relay's end-to-end encrypted chat running on your machine in under five minutes."
---

Relay is split into two sibling applications: `relay-backend`, a NestJS API server that handles auth, storage, and WebRTC signaling, and `relay-app`, a Next.js 16 frontend. Both need to be running at the same time during local development. If you skip the database step, the backend falls back to `InMemoryChatStrategy` automatically — messages live in server memory and are wiped on restart, but everything else works without a Postgres connection.

<Steps>
  <Step title="Clone the repository">
    Clone the repository and enter the root directory. Both applications live as sibling folders inside it.

    ```bash
    git clone https://github.com/humzasadiq/DesignPattern.git relay
    cd relay
    ```
  </Step>

  <Step title="Install dependencies">
    Install dependencies for both apps. Each has its own `package.json` — there is no shared monorepo tooling, so you run `npm install` twice.

    ```bash
    # Frontend — Next.js 16, libsodium, Socket.io client, Zustand
    cd relay-app && npm install

    # Backend — NestJS 11, Prisma 6, Passport, Socket.io server
    cd ../relay-backend && npm install
    ```
  </Step>

  <Step title="Configure the backend environment">
    Copy the example env file and fill in the values you need.

    ```bash
    cp relay-backend/.env.example relay-backend/.env
    ```

    ```ini
    # --- Database (leave DATABASE_URL empty to run in Temporary/in-memory mode) ---
    DATABASE_URL=

    # --- Server ---
    PORT=4000
    CORS_ORIGIN=http://localhost:3000

    # --- Auth ---
    JWT_ACCESS_SECRET=change-me
    JWT_REFRESH_SECRET=change-me
    JWT_ACCESS_TTL=15m
    JWT_REFRESH_TTL=30d

    # --- Cloudinary (optional until M5) ---
    CLOUDINARY_CLOUD_NAME=
    CLOUDINARY_API_KEY=
    CLOUDINARY_API_SECRET=
    ```

    <Note>
      Leave `DATABASE_URL` empty to skip Postgres entirely. The backend detects the missing variable at startup and switches to `InMemoryChatStrategy`, which stores all messages in plain `Map` objects. This mode is ideal for graders, demos, and offline development — no database required.
    </Note>

    <Warning>
      Change both JWT secrets before exposing the server to any network. The placeholder value `change-me` is intentionally weak and will not protect tokens in a real environment.
    </Warning>
  </Step>

  <Step title="Run database migrations (Postgres only)">
    If you set a `DATABASE_URL` pointing at a Postgres instance (local or [Neon](https://neon.tech) free tier), apply the Prisma migrations to create the schema.

    ```bash
    cd relay-backend
    npx prisma migrate dev
    ```

    This creates all eight models: `User`, `KeyBundle`, `Conversation`, `Membership`, `ConversationKey`, `Message`, `MediaAsset`, and `Session`. Skip this step entirely if you left `DATABASE_URL` empty.

    <Tip>
      To inspect the database in a browser GUI after migrations, run `npx prisma studio` from the `relay-backend` directory.
    </Tip>
  </Step>

  <Step title="Start both servers">
    Open two terminal tabs and start each app in watch mode.

    <CodeGroup>
      ```bash Backend
      cd relay-backend
      npm run start:dev
      ```

      ```bash Frontend
      cd relay-app
      npm run dev
      ```
    </CodeGroup>

    The backend listens on **http://localhost:4000** and the frontend on **http://localhost:3000**. Open the frontend in your browser and create an account to begin chatting.

    <Info>
      `npm run start:dev` runs `nest start --watch`, which rebuilds the backend on every file save. The Next.js dev server provides the same hot-reload behaviour on the frontend side.
    </Info>
  </Step>
</Steps>
